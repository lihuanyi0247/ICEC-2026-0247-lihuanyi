# 课题 02：个人手机多工况发热与掉电实测

## 1. 实验设计

| 项 | 设置 |
|---|---|
| 工况 | 待机 / 短视频 / 导航·拍摄 / 高帧率游戏（4 种） |
| 每工况时长 | 30 分钟 |
| 采样间隔 | 每 5 分钟记一次 → 每工况 7 个点（0/5/10/…/30） |
| 记录字段 | 电量%、电池温度、电压、屏幕亮度、前台应用、室温 |
| 控制变量 | 同一部手机、同一房间、同一室温、同一起始电量区间、全程不充电、飞行模式关（但关闭通知） |
| 数据量 | 4 工况 × 7 时点 = **28 行**（要求 ≥24 组，多录几个点更稳） |

**为什么每 30 分钟要冷却间隔**：温度有热惯性。如果待机测完立刻打游戏，
起始温度已经被抬高了，温升数据不可比。**每两个工况之间静置 10 分钟回温**。

**起始电量怎么控**：不要都从 100% 开始（充满后系统会在 90~100% 之间做涓流，
耗电曲线不线性）。建议每段都从 **80% 左右** 开始，做完一个工况充回去。

## 2. 怎么读温度（按可行性排序）

| 方法 | 精度 | 说明 |
|---|---|---|
| `AIDA64`（Android） | ±0.5 °C | 直接显示 battery temperature，最省事 |
| `AccuBattery`（Android） | ±0.5 °C | 同上，还能看放电电流 |
| 系统「电池」页面 / 工程模式 `*#*#6485#*#*` | ±1 °C | 免装 App |
| iPhone | — | 没有公开 API。用红外测温枪测背板，或 `iMazing` 读电池信息 |
| 外接红外测温枪 | ±2 °C | 测背板温度，与电芯温度差 1~2 °C，报告里写明 |

**报告中必须声明测温方式**，不同方式的绝对值不可比，这是面试官会问的点。

## 3. 操作步骤

1. 新建 `raw_data/记录表.csv`（复制 `记录表-示例格式.csv` 的表头，**把示例数字全删掉**）。
   > ⚠️ `记录表-示例格式.csv` 里的数字是**编的，只示范格式**。绝不能留作提交数据。
2. 手机充到 80% → 静置 5 分钟 → 记录起始值。
3. 按 `待机 → 短视频 → 导航拍摄 → 高帧率游戏` 顺序，每段 30 分钟，
   每 5 分钟看一眼记一次。定个 5 分钟循环的闹钟，别靠记性。
4. 每段之间**静置 10 分钟**回温，充电补回 80%。
5. 全程拍 1~2 张**同框照**（手机屏幕显示电量 + 你的手/环境），放 `../figures/`。

### 3.1 更省事、证据也更硬的做法：用 adb 自动采

手工抄数最大的软肋是**时间点无法自证**。手机开 USB 调试后，`collect_t02_adb.py`
每 30 秒直接读一次电池控制器，时间戳由电脑打，原文 `dumpsys` 一并留档：

```bash
python collect_t02_adb.py --check                    # 先确认能连上
python collect_t02_adb.py --cond 待机 --min 30 --room 22
python collect_t02_adb.py --cond 短视频 --min 30 --room 22
python collect_t02_adb.py --cond 导航拍摄 --min 30 --room 22
python collect_t02_adb.py --cond 高帧率游戏 --min 30 --room 22
```

产出直接追加进 `raw_data/记录表.csv`（表头一致，`analyze_t02.py` 直接吃），
另存 `raw_data/adb_raw_<工况>.txt` 原始报文。**30 秒一采而不是 5 分钟**，
是为了看清"电量掉 1%"的台阶形状 —— 事后按 5 分钟重采样，两种粒度都有。
好处是这 4 段可以边做别的事边挂机（正好用来做课题 10 的计时）。

## 6. 面试可能追问

| 问题 | 准备方向 |
|---|---|
| 你的功率是算出来的还是测出来的？ | 算的。基于电量变化率 × 标称容量 × 额定电压，误差来源有三条：电量计精度（±1%）、容量衰减（用了一年的电池实际容量低于标称）、电压随 SoC 变化（我用了固定值）。 |
| 为什么温升比功耗更能说明问题？ | 功耗是瞬时量，温度是热量累积的积分，反映散热能力。同样 6W，机身薄的手机温度更高 —— 这才是用户体验的差异。 |
| 待机功耗为什么可能偏低？ | 关闭屏幕后系统进入 Doze，某些后台被冻结。真实"待机"（有消息推送）会更高。我的实测条件是 XX，属于理想待机。 |
