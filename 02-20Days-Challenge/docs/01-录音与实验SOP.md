# 录音与实验 SOP（照着做，约 2.5 小时）

> 这份文件是"现场操作手册"。所有需要你亲手做的动作都写在这里；
> 代码部分已经写好，你只要保证**数据是真的、命名是对的**。

## 0. 一句话流程

> 录 75 个 10 秒音频（5 工况 × 3 次实验 × 5 段）→ 拍 10 张带 EXIF 的现场照 →
> 跑 `python src/run_all.py` → 出报告 → 提交。

## 1. 准备（15 分钟）

### 1.1 你要有的东西

| 项 | 要求 | 备注 |
|---|---|---|
| 电风扇 | 有 2 档以上，最好是 3 叶或 5 叶 | 台扇/落地扇都行 |
| 手机 | 任意智能机 | 就是你的主力机也能用 |
| 录音 App | 能导出 **WAV** 且能设置采样率 | 见 1.2 |
| 胶带 / 硬币 | 约 2g（一枚 1 元硬币 6.1g，半枚≈3g；胶带缠几圈更灵活） | 做"扇叶失衡"用 |
| A4 纸 / 硬纸板 | 一张 | 做"进风遮挡"用 |
| 卷尺 | 量 30cm 距离 | 没有就用 A4 纸长边（29.7cm）比划 |
| 安静环境 | 尽量关掉空调、关窗 | 但**不要为了安静而造假**，录到真实底噪反而好 |

### 1.2 录音 App 设置（关键，选错格式整条流水线读不了）

**Android**：
- 推荐 App：`RecForge II`（可设 WAV / 44100Hz / 单声道 / 16bit）或系统自带录音机的"无损"选项。
- 小米/华为/OPPO 自带录音机 → 设置里找"录音格式 → wav"。

**iPhone**：
- 系统"语音备忘录"只能出 m4a。两个办法：
  1. 用 `Voice Record Pro`（免费，可直接导出 WAV）——**推荐，省一步**；
  2. 或者照常录 m4a，改名时加 `--convert`，用本机已装好的 ffmpeg 真转码
     （`rename_recordings.py` 会自动找到
     `…\envs\default\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v9.0.2.exe`，
     转成 44.1kHz 单声道 16bit，原件自动留档到 `_原始格式/`）。

**通用要求**：
- 采样率 **44100 或 48000**，单声道，不要开任何"降噪/美声/自动增益"。
- **关闭"自动增益控制（AGC）"**——它会把你故意制造的响度差异抹平，直接毁掉实验。
- 关掉微信/QQ 提示音，手机开**飞行模式**（但不能断 WiFi，App 可能需要）。

> **实测记录（2026-11-18 试录）**：本机手机自带录音机输出的是
> **24 bit / 双声道 / 48 kHz**，10.8 秒就有 3.0 MB。这个格式**分析完全读得了**
> （`audio_io.py` 内置 24bit 三字节解析），但 75 段会到 **223 MB**，仓库撑不住。
> 处理办法（**不用重录**）：导入时给 `rename_recordings.py` 加 `--to16`，
> 一步转成 16bit / 单声道 / 44.1kHz，实测 74.3 MB → 22.8 MB，
> 且源文件原封不动留在 `D:\录音\S1` 当 24bit 母版，溯源时能出示。
> 详见 `_私房-面试与作战/06-24bit录音怎么办.md`。
>
> 能改 App 设置就顺手改成单声道 + 16bit，省一次转码；改不了也能走完全程。

### 1.3 目录与命名（错一个字脚本就认不出）

```
02-20Days-Challenge/raw/
├── S1/   FAN_N1_S1_01.wav ... FAN_S0_S1_05.wav   （25 个）
├── S2/   FAN_N1_S2_01.wav ... FAN_S0_S2_05.wav   （25 个）
└── S3/   FAN_N1_S3_01.wav ... FAN_S0_S3_05.wav   （25 个）
```

命名规则：`设备_工况_会话_序号.wav`

| 段位 | 取值 | 说明 |
|---|---|---|
| 设备 | `FAN` | 电风扇。换设备就用 `DRY`（吹风机）/`BIKE`（单车） |
| 工况 | `N1` `N2` `F1` `O1` `S0` | 见第 3 节 |
| 会话 | `S1` `S2` `S3` | **三次不同的实验**，不是三个文件夹随便放 |
| 序号 | `01`~`05` | 同一会话同一工况的第几段 |

> 为什么非要分 S1/S2/S3：同一次连续录制的文件共享同一房间混响、同一段背景噪声、
> 同一个手机位置。分开录三次，模型才没法靠"房间指纹"作弊，留一会话验证才有意义。
> **S2、S3 请换到不同时间/不同位置录**（比如 S1 在宿舍晚上、S2 在宿舍中午、
> S3 在实训室或换个房间角落）。

## 2. 摆位（这一段决定数据质量，别省）

```
        ┌──────────┐
        │  电风扇   │  ← 出风口正对手机
        └──────────┘
             │
             │  30 cm（用卷尺量，三次会话保持一致）
             │  手机与扇心同高
             ▼
        ┌──────────┐
        │   手机    │  ← 平放在桌面/书堆上，屏幕朝上，麦克风朝风扇
        └──────────┘
```

**四条铁律**：

1. **手机必须固定**，不能手持。手抖 → 0~20Hz 低频噪声 → 污染所有低频特征。
2. **距离 30cm，三次会话都量**。距离一变，低频衰减立刻变，模型会把它当成工况变化。
3. **手机麦克风位置对准风扇**（一般在手机底部或顶部，查一下你的机型）。
4. 每次录音前**等 2 秒再按开始**，避免手指摩擦声被录进开头。

## 3. 五种工况怎么做（关键：可复现，不靠感觉）

| 代码 | 名称 | 具体做法 | 常见错误 |
|---|---|---|---|
| `N1` | 正常·低档 | 开机 → 按到最低档 → 等转速稳定 5 秒 → 录 10 秒 | 刚开机就录，转速还在爬升 |
| `N2` | 正常·高档 | 按到最高档 → 等 5 秒 → 录 10 秒 | — |
| `F1` | 扇叶失衡 | **关机**，在其中**一片**叶片外缘贴 2g 配重（同一片，每次都同一位置）→ 开高档 → 等 5 秒 → 录 10 秒 | 配重位置每次不一样，等于每次都是新工况；配重太大风扇会晃到危险 |
| `O1` | 进风遮挡 | 保持高档，用 A4 纸遮住**进风侧（后网罩）的一半面积** → 等 3 秒 → 录 10 秒 | 遮出风侧（那是另一种工况）；遮满（会过热） |
| `S0` | 停机基线 | **关掉风扇**，等 5 秒（让扇叶完全停）→ 录 10 秒 | 忘了关；或环境里有别人说话 |

**每个工况录 5 段**，段与段之间停 3 秒。每段 10 秒左右即可（9~12 秒都能用）。

> `F1` 和 `O1` 会改变风扇状态，所以一组的顺序建议：
> `S0 → N1 → N2 → F1 → O1`（先录不需要改装的，再改装，最后遮挡）。
> 每换一个会话，重做一遍改装动作 —— 这才是"独立实验"。

**安全提醒**：贴配重后如果风扇剧烈晃动、发出撞击声，**立刻关机**，减少配重。
你要的是"轻微失衡"，不是"拆机"。

## 4. 拍照（10 张，必须有 EXIF）

用**手机原生相机**拍（不要用微信拍），至少拍：

1. 整体摆位（能看到卷尺和 30cm 距离）—— 2 张
2. `N1`、`N2` 运行中的风扇 —— 各 1 张
3. `F1` 配重特写（能看清贴在哪片叶片、什么位置）—— 1 张
4. `O1` 遮挡状态（能看清遮了哪一半）—— 1 张
5. 手机录音界面（显示采样率/WAV）—— 1 张
6. 电脑上跑脚本的屏幕（可选，但很有说服力）—— 1 张

照片放进 `02-20Days-Challenge/photos/`。

> ⚠️ **千万不要用微信/QQ 传照片**，会剥掉 EXIF 拍摄时间和机型信息 ——
> 而 `src/selfcheck.py` 正是靠 EXIF 来证明"这是现场拍的"。
> 用数据线拷，或用「文件传输助手 → 原图」。

## 5. 盲测集（10 分钟，决定交付③能不能拿分）

盲测视频的说服力，全在"这批文件模型从来没见过"。

1. 隔一天（或至少隔一次会话），重新摆位，**随意**安排 5 种工况各 2~3 次，
   **不要按顺序录**，录完不要回看。
2. 存到 `02-20Days-Challenge/raw_blind/`，命名 `BLIND_<真实工况>_<序号>.wav`，
   例如 `BLIND_F1_01.wav`、`BLIND_N2_02.wav`。
3. 运行：

```bash
python src/predict_live.py --dir raw_blind
```

会输出逐文件预测 + 真实标签 + 准确率，并落表 `results/blind_test.csv`。

4. **录屏**：把终端窗口放大（字号调到能看清），先 `ls raw_blind` 展示文件存在，
   再运行命令，让观众看到预测逐条出现。**不要剪辑**，卡顿也保留 —— 真实感比流畅重要。

## 6. 三次会话怎么安排（建议）

| 会话 | 时间 | 位置 | 目的 |
|---|---|---|---|
| `S1` | 今晚 | 宿舍，风扇摆桌上 | 基线 |
| `S2` | 明天中午/晚上 | 宿舍，但换个角落或换桌面 | 引入位置差异 |
| `S3` | 后天 | 教学楼/实训室（带风扇过去） | 引入房间混响差异 |

如果实在只有一个地方，那就至少换**时间段**（白天有环境噪声 / 深夜安静），
并在报告里如实写明"三个会话共享同一房间，仅时段不同"——诚实比完美值钱。

## 7. 常见坑（都是真实踩过的）

| 现象 | 原因 | 解决 |
|---|---|---|
| 脚本报"太短" | 录了 3 秒 | 每段 ≥5 秒，最好 10 秒 |
| 脚本报"文件名不合规" | 用了中文/空格/大写错 | 严格 `FAN_N1_S1_01.wav` |
| 读不了音频 | 录成 m4a/amr | 改名时加 `--convert`（本机 ffmpeg 已就绪），或改 App 设置重录 |
| 削波比例 >1% | 录音增益太大 | App 里把输入音量降到 70% 左右重录 |
| 准确率异常高（>98%） | 数据泄漏（同一文件同时进训练和测试） | 检查是否只跑了一个会话；确认 LOSO 生效 |
| 某工况召回率 0% | 该工况只录了 2~3 段 | 补齐到 15 段 |
| 准确性很低（<60%） | 手机没固定 / 距离每次都变 / 忘关 AGC | 按第 2 节重录一遍 |
